# 作业 4：CampusClaw 文件上传逻辑分析

> 分析对象：本人学期仓迭代 1 的上传实现（`backend/internal/materials/materials.go`、`backend/internal/auth/auth.go`），规约依据 `openspec/changes/add-auth-rbac-class-knowledge/specs/auth-upload/spec.md` R2/R4/R5。

## 一、结论先行

- **支持的文件类型：仅 `.txt` 和 `.md` 两种**（扩展名白名单）。
- **`.txt` / `.md` 以外的文件：不支持**。任何其他扩展名（包括 `.exe`、`.pdf`、`.docx`、伪装成 `.md.exe` 的双扩展名）都会在上传入口被直接拒绝，返回 HTTP 400，且数据库与磁盘均不产生任何记录或文件。
- 除类型外还有两道独立闸门：**大小上限**（超限 413）与**内容校验**（必须是非空 UTF-8 文本，否则 400）。三类失败都已实测验证。

## 二、上传请求的完整处理链路

接口：`POST /api/materials`（`multipart/form-data`，文件字段名 `file`）。浏览器 → Nginx 同源反代 → Go 后端，全部校验都在服务端完成。代码中的执行顺序如下：

```
① 会话校验        未登录 → 401（响应体不含任何业务数据）
② 角色校验        非教师（学生）→ 403，此时还未读取任何文件内容，库与磁盘零变化
③ 大小闸门        http.MaxBytesReader 包住请求体：超过 MAX_UPLOAD_BYTES（默认 1MB）
                  在【读完整个请求体之前】截断 → 413，不产生临时文件
④ 解析表单        ParseMultipartForm 失败 → 400
⑤ 扩展名白名单    filepath.Ext 取最后一个扩展名，仅放行 .txt / .md，
                  其余一律 400（.md.exe 这种双扩展名也拦得住）
⑥ 内容校验        读入字节流，必须是【非空 + 合法 UTF-8】文本，否则 400
⑦ 安全落盘        存储文件名由服务端用 16 字节随机数生成（如 3f731ba5….md），
                  客户端原始文件名只作展示标题，绝不参与路径构造（防 ../ 路径穿越）
⑧ 同事务入库      BEGIN → INSERT materials → INSERT knowledge_entries（解析出的正文）
                  → COMMIT；任一步失败整体 ROLLBACK 并删除已落盘文件
⑨ 返回 201        {"id": …, "title": …}
```

关键设计：**校验尽量前置**——类型、大小、内容三道闸门全部通过后才会写磁盘和数据库；而写库又包在一个事务里，所以任何失败路径都不会留下"半个文件"或"半条记录"（孤儿数据）。

## 三、为什么只支持 .txt / .md（白名单而非黑名单）

1. **黑名单无法穷举危险类型**：可执行文件、脚本、压缩包、伪装扩展名花样无穷，逐个禁止必然漏网；白名单"只放行明确安全的类型"才是默认拒绝的正确姿势。
2. **解析能力边界**：本迭代知识库只存"可查询的纯文本正文"，解析器按 UTF-8 纯文本处理；PDF / Word / 图片需要额外的解析管道，已明确写入 `proposal.md` 的 Non-goals（非目标），留待后续迭代。
3. **可判定性**：规约把三类失败（扩展名 / 大小 / 内容）分别写成了可判定的 Scenario 和预期状态码，验收时可以逐条跑失败路径，而不是"看上去传不上去"。

## 四、实测证据（Docker Compose 环境，2026-09-23 实际执行）

| 测试输入 | 期望 | 实际结果 | 副作用检查 |
| --- | --- | --- | --- |
| 教师上传合法 `demo.md`（含 `<script>` 文本） | 201 入库 | `201 {"id":3,"title":"demo.md"}` | `materials`、`knowledge_entries` 两表各 +1 行且互相关联，class_id=1（A 班） |
| 教师上传 `t.exe` | 400 拒绝 | `400 {"error":"仅支持 .txt / .md 文件"}` | 两表行数不变、uploads 目录无新文件 |
| 教师上传 2MB 的 `big.md`（超限） | 413 拒绝 | `413 {"error":"文件超过大小上限"}` | 同上，无残留 |
| 教师上传非法编码的 `bad.md`（`\xff\xfe…`） | 400 拒绝 | `400 {"error":"文件内容不是非空的 UTF-8 文本"}` | 同上，无残留 |
| 学生 A1/B1 上传合法 `.txt` | 403 拒绝 | `403 {"error":"仅教师可执行此操作"}` | 上传前后两表行数与 uploads 目录逐字节一致 |
| 表单塞入 `class_id=2`（B 班）上传 | 忽略该字段 | 落库记录 `class_id=1` | 数据归属只取服务端会话 |

补充佐证：下载不依赖静态路径——上传目录未对 Nginx 暴露，直接猜 `http://localhost:8080/uploads/<文件名>` 取不到文件；文件只能经鉴权接口 `GET /api/materials/{id}/file` 下载，跨班返回与"不存在"同形的 404。

## 五、小结

上传逻辑的主线是三句话：**谁能传**（教师，服务端会话角色判定）、**传什么**（白名单 `.txt`/`.md` + 大小上限 + 非空 UTF-8）、**怎么落**（服务端命名落盘 + 双表同事务，失败零残留）。`.txt`/`.md` 以外的文件在当前迭代不被支持，这是规约层面的明确取舍（白名单 + Non-goals），而非实现遗漏。
